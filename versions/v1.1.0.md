# 🎉 create-uni-app v1.1.0 发布

> 结构化生成 —— 状态管理、路由实例与守卫分文件封装，工程骨架更规范

**发布日期**：2026-09-01 · **版本**：`1.1.0` · **License**：MIT

v1.1.0 聚焦**生成结构的规范性与可维护性**：把此前挤在主入口里的逻辑拆到各自独立文件，让生成出的工程「功能内聚、入口干净」，同时输出更规范、版本更对齐。

---

## 本轮更新

### 🗃️ 状态管理：统一 `stores/` 目录 + 结构化封装

- Pinia / Vuex 统一归入 `stores/` 目录（原 Vuex 使用 `store`），主入口引用一致
- Pinia 新增 `stores/index`，通过 `createPiniaStore()` 创建实例并在其内部注册持久化插件，主入口只保留 `app.use(pinia)`

### 🧭 路由：实例与守卫分离

- 生成 `src/router` 目录：`index` 创建路由实例（`createRouter` + 插件），`guards` 独立维护全局 `beforeEach` / `afterEach` 守卫示例
- 主入口只 `import router from './router'` + `app.use(router)`，不再内联创建逻辑
- 纯 uni-router 方案仍额外生成手写 `src/router.config`

### ⚙️ 配置自动适配语言

- TS 项目生成 `vite.config.ts`，JS 项目仍为 `vite.config.js`，构建配置随脚本语言自适应

### 📦 更规范的输出

- `package.json` 的 `dependencies` / `devDependencies` 按字母序标准化
- 默认 uni-app 运行时版本对齐官方 Vue3 通道（随时可用 `npx @dcloudio/uvm@latest` 同步最新）

### 🧰 更友好的失败提示

- 依赖自动安装失败时输出真实退出码 / 启动错误及手动重试指引，便于定位根因
- 修复 Vuex 不启用持久化时 `stores/index` 中的多余空行

## 快速上手

```bash
npm i -g @meng-xi/create-uni-app
create-uni-app my-app

cd my-app
npm run dev:h5          # 启动 H5
npm run dev:mp-weixin   # 启动微信小程序
```

同时支持 `npx @meng-xi/create-uni-app my-app` 免安装直接使用。
